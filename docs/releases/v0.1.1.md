# DeepShell Agent v0.1.1 Release-Hardening Closeout

> **Product:** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **Version:** `v0.1.1`
>
> **Status:** Development baseline complete; binary release and user manual acceptance are still separate gates.
>
> **Date:** 2026-09-10

## 1. Summary

`v0.1.1` hardens the public `v0.1.0` MVP baseline for outside testers and future binary releases. It does not expand the architecture boundary: Tauri still owns the desktop shell and process lifecycle, the official DSH Web UI owns the base interaction, and the DSH Runtime owns Agent semantics.

This version adds release staging, diagnostics, package reporting, SBOM generation, vulnerability-audit entrypoints, a Windows x64 packaging route, and a clearer General/Coding/Work Mode surface.

## 2. Implemented scope

| Area | Status | Notes |
|---|---|---|
| Version metadata | Implemented | App, Tauri, Rust package, runtime lock, and first-party DSH Bundle now use `0.1.1`. |

| Agent Mode entry | Implemented | Reuses the official DSH Agent Preset UI for selection and adds a DeepShell Mode header indicator through a public Slot. |
| Diagnostics bundle | Implemented | `pnpm diagnostics:collect` exports local, redacted diagnostics under ignored staging. |

| Release staging | Implemented | `pnpm release:stage` prepares checksums, release-note draft, and support assets without publishing. |
| SBOM baseline | Implemented | `pnpm sbom:generate` derives a machine-readable baseline from the license inventory. |
| Vulnerability audit baseline | Implemented | `pnpm security:audit` scans Node/DSH/Rust where tools are available; `--dry-run` is available for deterministic checks. |
| Windows x64 route | Implemented as route/checklist | Added `pnpm release:windows:check` and a manual GitHub Actions packaging workflow. Real Windows installer acceptance remains pending. |
| Install/upgrade/uninstall checklist | Implemented as checklist | Local process checklists exist under `docs/plans/`; public release notes should only carry summary status. |

## 3. Explicit non-scope and remaining gates

This closeout does not claim:

- macOS Developer ID signing;
- Apple notarization;
- Windows code signing;
- Windows installer pass on real hardware or CI;
- public binary release publication;
- automatic GitHub release creation;
- telemetry or remote diagnostic upload;
- runtime slimming by removing DSH runtime capabilities.

Windows x64 installer validation remains a separate Roadmap item (`REL-017`). Signed binary distribution remains a separate Roadmap item (`REL-018`).

## 5. Public/private artifact boundary

Committed public materials may include:

- source scripts;
- tests;
- public Roadmap and release closeout documents;
- README / third-party notice updates;
- manual GitHub Actions workflow configuration.

Ignored/local materials remain outside the public source repository by default:

- `docs/plans/`;
- `runtime/staging/`;
- `runtime/node/`;
- `runtime/dsh/`;
- `runtime/profile-template/`;
- local `.app`, `.dmg`, `.exe`, logs, screenshots, diagnostics, and evidence files.

## 6. Release recommendation

`v0.1.1` is ready for manual acceptance and binary-release preparation. Before publishing binaries:

1. manually verify macOS install/upgrade/uninstall behavior using the generated `v0.1.1` DMG;
2. run the Windows workflow or validate on a Windows x64 machine before attaching any Windows installer;
3. install `cargo-audit` and rerun `pnpm security:audit` if Rust advisory coverage is required for release sign-off;
4. keep the release marked as Developer Preview until signing/notarization gates are complete.
