# DeepShell Agent v0.1.0 MVP 收口

> **产品：** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **版本：** `v0.1.0`
>
> **阶段：** MVP（Minimum Viable Product，最小可用版本）
>
> **状态：** Public source baseline complete；binary release gates pending
>
> **收口日期：** 2026-09-09

## 1. 收口结论

DeepShell Agent `v0.1.0` 已完成 MVP 源码基线收口。

本版本将 `v0.0.1` POC 验证过的“官方 DSH Web UI + Tauri 桌面壳 + pinned DSH runtime”路线扩展为可继续公开协作的最小产品基线：

1. 应用版本升级到 `0.1.0`。
2. 桌面壳继续使用 Tauri 2 + Rust。
3. 运行时继续使用 bundled Node.js + pinned official DSH。
4. 官方 DSH React Web UI 仍是唯一 Agent Web Client。
5. DeepShell 差异化能力通过 DSH Bundle/Profile/Preset/Plugin 扩展，不 fork 官方 UI。
6. `deepshell-coding`、`deepshell-work` 与 legacy `deepshell` Preset 已形成当前 Profile 基线。
7. Web Search、Web Fetch、多 Provider、权限、凭据和诊断边界已纳入 MVP 源码与文档基线。
8. macOS arm64 构建链路已具备本地应用包与安装镜像生成能力。
9. Windows x64 runtime 资产、路径和构建路线已进入基线，但公开二进制发布前仍需 Windows 真机或 CI 验收。

本文件记录的是公开源码仓库可保留的 MVP 收口事实，不表示已经完成正式签名、公证、Windows 安装包验证或面向公众的二进制发布。

## 3. 已完成范围

### 3.1 桌面与运行时

- Tauri/Rust 单主窗口和单实例模型。
- Sidecar 启动、动态回环端口、进程作用域 token 清理、Ready Gate 和基础恢复。
- Bundled Node.js 与 pinned official DSH runtime。
- macOS arm64 与 Windows x64 的 Node runtime 锁定清单。
- 平台化 runtime manifest、校验脚本和包内容比较脚本。
- 独立 DSH_HOME，避免污染用户已有 DSH CLI 环境。

### 3.2 DSH Profile 与 Agent Mode

- `deepshell-desktop` Bundle 作为 MVP 主集成层。
- `deepshell-coding` Preset 面向代码理解、修改、Shell/Test/Git 工作流。
- `deepshell-work` Preset 面向 Web research、本地文本/Markdown 产出和普通文件读写。
- legacy `deepshell` Preset 保留，用于兼容旧 POC 会话。
- Coding/Work Mode 继续复用官方 DSH Session、Tool、Approval 和 Credential 语义。

### 3.3 模型、Web 工具与凭据

- DeepSeek 官方 Provider 路线。
- OpenAI-compatible API 路由能力。
- Responses API 路由能力。
- 官方 Models Settings 和 `credentials-local` 凭据方案。
- DeepSeek Web Search 与公共 HTTP(S) Web Fetch。
- 正常流程、错误页、日志和诊断边界中的 Secret 脱敏要求。

### 3.4 安全与公开边界

- WebView 导航限制、loopback origin 边界和最小 Tauri capability。
- Workspace 内写入按官方 `workspace-write` 语义允许。
- Workspace 外写入、扩大权限和危险操作继续走官方 Approval/fail-closed 语义。
- 不引入 DeepShell 自有并行权限系统。
- 不把 `credentials-local` 描述为同一 OS 用户边界内的强隔离。
- `docs/plans/` 作为本地过程文档目录，不随公开源码仓库发布。

## 4. 明确不属于本版本

- 不 fork 官方 DSH Web UI。
- 不使用 Svelte 或自建平行 Agent Web UI。
- 不做 DOM monkey patch。
- 不导入 DSH 私有 React 组件或私有 import 路径。
- 不自研第二套 Agent、Session、Tool、Sandbox、Approval、Credential 或 Model Registry Runtime。
- 不实现 Keychain、Windows Credential Manager 或 Linux Secret Service Provider。
- 不实现独立 Git/Test/Terminal/Documents/Connectors 专属面板。
- 不实现 DOCX/PDF/PPTX/XLSX 原生解析和预览。
- 不实现 MCP/SaaS Connector、Plugin Marketplace、Auto Update 或多窗口。
- 不覆盖 Linux、Intel macOS、Windows arm64 或移动端。

## 6. 已知限制与风险接受

| 限制/风险 | v0.1.0 结论 | 后续处理 |
|---|---|---|
| DSH 上游仍处于 Developer Preview | 接受。当前锁定 `@deepseek-ai/dsh@0.1.2-rc.1`，不浮动升级。 | 后续升级必须重新跑 runtime/profile/package/E2E/安全边界回归。 |
| Windows 尚未完成公开发布验收 | 接受为源码基线限制。 | 在 Windows 真机或 CI 中完成 NSIS installer、WebView2、进程树和签名状态验证。 |
| macOS 未完成 Developer ID 签名和 notarization | 接受为源码基线限制。 | 正式二进制分发前完成签名、公证和 Gatekeeper 验证。 |
| `credentials-local` 同用户读取风险 | 接受。MVP 保持 DSH 官方凭据方案。 | 未来按 DSH Credential 公共契约评估系统凭据 Provider。 |
| 包体积仍偏大 | 接受。完整 Node.js 与完整 DSH runtime 是当前路线的一部分。 | 后续只做安全 slimming，不裁掉核心 DSH 能力。 |
| Work Mode 仍是最小闭环 | 接受。MVP Work Mode 主要覆盖 Web research、Markdown/text、本地文件读写。 | Office/PDF/PPTX/XLSX、复杂知识库和企业 Connector 后续单独设计。 |

## 7. 公开仓库边界

公开源码仓库保留：

- `README.md`
- `THIRD_PARTY_NOTICES.md`
- `AGENTS.md`
- `docs/architecture.md`
- `docs/roadmap.md`
- `docs/releases/`
- 源码、测试、构建脚本和锁定清单

公开源码仓库不提交：

- `docs/plans/` 本地过程文档；
- 完整 runtime、构建缓存和安装后的依赖树；
- 本地 `.app`、`.dmg`、Windows installer 或 E2E staging manifest；
- 未脱敏日志、截图、诊断包、手工验收原始记录或私有证据；
- 真实 API Key、Cookie、启动 token、Prompt、Tool Output 或用户本地路径。
