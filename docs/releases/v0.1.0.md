# DeepShell Agent v0.1.0 MVP Closeout

> **Product:** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **Version:** `v0.1.0`
>
> **Phase:** MVP (Minimum Viable Product)
>
> **Status:** Public source baseline complete; binary release gates pending
>
> **Closeout date:** 2026-09-09

## 1. Closeout conclusion

DeepShell Agent `v0.1.0` has completed the MVP source baseline closeout.

This version extends the `v0.0.1` POC path—official DSH Web UI + Tauri desktop shell + pinned DSH runtime—into a minimal product baseline suitable for public source collaboration:

1. The application version is upgraded to `0.1.0`.
2. The desktop shell continues to use Tauri 2 + Rust.
3. The runtime continues to use bundled Node.js + pinned official DSH.
4. The official DSH React Web UI remains the only Agent Web Client.
5. DeepShell differentiation is implemented through DSH Bundle/Profile/Preset/Plugin extension points, with no official UI fork.
6. `deepshell-coding`, `deepshell-work`, and legacy `deepshell` presets form the current Profile baseline.
7. Web Search, Web Fetch, multi-provider support, permissions, credentials, and diagnostic boundaries are included in the MVP source and documentation baseline.
8. The macOS arm64 build path can generate a local application package and disk image.
9. Windows x64 runtime assets, paths, and build route are part of the baseline, but public binary release still requires validation on Windows hardware or CI.

This file records MVP closeout facts that can stay in the public source repository. It does not claim formal signing, notarization, Windows installer validation, or public binary distribution readiness.

## 3. Completed scope

### 3.1 Desktop and runtime

- Tauri/Rust single-main-window and single-instance model.
- Sidecar startup, dynamic loopback port, process-scoped token cleanup, Ready Gate, and basic recovery.
- Bundled Node.js and pinned official DSH runtime.
- Node runtime lock manifest for macOS arm64 and Windows x64.
- Platform-aware runtime manifest, verification scripts, and package-content comparison scripts.
- Independent `DSH_HOME` so the user's existing DSH CLI environment is not polluted.

### 3.2 DSH Profile and Agent Mode

- `deepshell-desktop` Bundle as the MVP integration layer.
- `deepshell-coding` Preset for code understanding, editing, Shell/Test/Git workflows.
- `deepshell-work` Preset for web research, local text/Markdown output, and ordinary file read/write.
- Legacy `deepshell` Preset retained for old POC session compatibility.
- Coding/Work Mode continues to reuse official DSH Session, Tool, Approval, and Credential semantics.

### 3.3 Models, web tools, and credentials

- DeepSeek official Provider route.
- OpenAI-compatible API route.
- Responses API route.
- Official Models Settings and `credentials-local` credential scheme.
- DeepSeek Web Search and public HTTP(S) Web Fetch.
- Secret-redaction requirements for normal flows, error pages, logs, and diagnostics.

### 3.4 Security and public boundary

- WebView navigation restrictions, loopback origin boundary, and minimal Tauri capability.
- Workspace writes are allowed according to official `workspace-write` semantics.
- Out-of-workspace writes, permission expansion, and dangerous operations continue to use official Approval/fail-closed semantics.
- No DeepShell-owned parallel permission system.
- `credentials-local` is not described as strong isolation between processes running as the same OS user.
- `docs/plans/` remains a local process-document directory and is not published with the public source repository.

## 4. Explicitly out of scope

- No fork of the official DSH Web UI.
- No Svelte or custom parallel Agent Web UI.
- No DOM monkey patching.
- No private DSH React component or private import path dependency.
- No second Agent, Session, Tool, Sandbox, Approval, Credential, or Model Registry Runtime.
- No Keychain, Windows Credential Manager, or Linux Secret Service Provider.
- No dedicated Git/Test/Terminal/Documents/Connectors panels.
- No native DOCX/PDF/PPTX/XLSX parsing or preview.
- No MCP/SaaS Connector, Plugin Marketplace, Auto Update, or multi-window support.
- No Linux, Intel macOS, Windows arm64, or mobile coverage.

## 6. Known limitations and accepted risks

| Limitation/risk | v0.1.0 conclusion | Follow-up |
|---|---|---|
| DSH upstream remains in Developer Preview | Accepted. `@deepseek-ai/dsh@0.1.2-rc.1` is pinned and not floated. | Every upgrade must rerun runtime/profile/package/E2E/security-boundary regressions. |
| Windows public release validation is not complete | Accepted as a source-baseline limitation. | Validate NSIS installer, WebView2, process tree, and signing state on Windows hardware or CI. |
| macOS Developer ID signing and notarization are not complete | Accepted as a source-baseline limitation. | Complete signing, notarization, and Gatekeeper verification before formal binary distribution. |
| Same-user read risk in `credentials-local` | Accepted. MVP keeps the official DSH credential scheme. | Evaluate system credential providers through DSH's public Credential contract later. |
| Package size remains large | Accepted. Full Node.js and full DSH runtime are part of the current route. | Only perform safe slimming; do not remove core DSH capabilities. |
| Work Mode remains a minimal loop | Accepted. MVP Work Mode focuses on web research, Markdown/text, and local file read/write. | Design Office/PDF/PPTX/XLSX, complex knowledge bases, and enterprise connectors separately. |

## 7. Public repository boundary

The public source repository keeps:

- `README.md`
- `THIRD_PARTY_NOTICES.md`
- `AGENTS.md`
- `docs/architecture.md`
- `docs/roadmap.md`
- `docs/releases/`
- Source code, tests, build scripts, and lock manifests

The public source repository does not commit:

- Local `docs/plans/` process documents;
- Full runtime, build cache, or installed dependency trees;
- Local `.app`, `.dmg`, Windows installer, or E2E staging manifest;
- Unredacted logs, screenshots, diagnostic bundles, raw manual acceptance records, or private evidence;
- Real API keys, cookies, startup tokens, prompts, tool outputs, or user-local paths.
