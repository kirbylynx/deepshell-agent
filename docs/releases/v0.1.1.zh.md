# DeepShell Agent v0.1.1 发布硬化收口

> **产品：** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **版本：** `v0.1.1`
>
> **状态：** 开发基线已完成；二进制发布和用户手工验收仍是独立门禁。
>
> **日期：** 2026-09-10

## 1. 摘要

`v0.1.1` 在公开的 `v0.1.0` MVP 基线上做发布硬化，让项目更适合外部试用者和后续二进制发布流程。它不扩大架构边界：Tauri 仍负责桌面壳和进程生命周期，官方 DSH Web UI 仍负责基础交互，DSH Runtime 仍负责 Agent 语义。

本版本新增 release staging、诊断包、包体积报告、SBOM、漏洞扫描入口、Windows x64 打包路线，以及更清晰的 General/Coding/Work Mode 入口。

## 2. 已实现范围

| 领域 | 状态 | 说明 |
|---|---|---|
| 版本元数据 | 已实现 | App、Tauri、Rust package、runtime lock 和一方 DSH Bundle 已更新为 `0.1.1`。 |

## 3. 明确不做范围和剩余门禁

本收口不声明：

- macOS Developer ID 签名；
- Apple notarization；
- Windows code signing；
- Windows installer 在真机或 CI 中通过；
- 公开二进制 release 已发布；
- 自动创建 GitHub release；
- 遥测或远程诊断上传；
- 通过删除 DSH runtime 能力来瘦身。

Windows x64 installer 验收仍是独立 Roadmap 项 `REL-017`。签名二进制分发仍是独立 Roadmap 项 `REL-018`。

## 5. 公开/本地 artifact 边界

可以提交到公开仓库的材料包括：

- 源码脚本；
- 测试；
- public Roadmap 与 release closeout 文档；
- README / third-party notices 更新；
- 手动触发的 GitHub Actions workflow 配置。

默认仍留在本地 ignored 范围内的材料包括：

- `docs/plans/`；
- `runtime/staging/`；
- `runtime/node/`；
- `runtime/dsh/`；
- `runtime/profile-template/`；
- 本地 `.app`、`.dmg`、`.exe`、日志、截图、诊断包和验收证据。

## 6. 发布建议

`v0.1.1` 已准备好进入手工验收和二进制发布准备。发布二进制前建议：

1. 使用已生成的 `v0.1.1` DMG 手工验证 macOS 安装/升级/卸载；
2. 在附加任何 Windows installer 之前，先运行 Windows workflow 或在 Windows x64 真机上验收；
3. 如果 release sign-off 需要 Rust advisory 覆盖，先安装 `cargo-audit` 并重跑 `pnpm security:audit`；
4. 在签名/公证门禁完成前，release 继续标记为 Developer Preview。
