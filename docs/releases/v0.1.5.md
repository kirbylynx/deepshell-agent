# DeepShell Agent v0.1.5 Single-File Runtime Release

> **Product:** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **Version:** `v0.1.5`
>
> **Release nature:** a runtime-architecture release: the installed Node.js + DSH dependency tree is replaced by a platform-specific Enhanced SEA (single executable application) sidecar, so installs no longer carry tens of thousands of runtime files while Sessions, Providers, credentials, and the official DSH Web UI stay unchanged.
>
> **Status:** **Prepared as an unsigned prerelease candidate.** Windows x64 W0–W3 acceptance passed on the final clean-rebuild artifacts (installed/portable matrix, upgrade and rollback paths, on-device SEA evidence, and the user's real-device tool re-test). The W3b rework then rebuilt the assets from a further clean commit and re-ran the affected evidence: real non-dry-run security audits, a `windows-preflight-pass` route check, the install/uninstall regression, a fresh app boot, and the on-device, report and size gates. The macOS MAC-01 to MAC-09 items passed in the macOS round. CI run `36319913120` (success, head `6e660f3`) is recorded as the independent same-commit build gate only. Developer ID/notarization and Windows code signing are **not** done.
>
> **Date:** 2026-09-27

## 1. Scope

- **SEA single-file Runtime** (`REL-028`): each installer ships one platform-specific `deepshell-runtime.exe` (Enhanced SEA, Zstd, `@yao-pkg/pkg@6.22.0`) instead of the extracted `runtime/node` + `runtime/dsh` tree; end users no longer install or carry Node.js, npm, pnpm, or DSH on disk, and none of them are required to be present on the machine;
- **Controlled runtime cache**: native addons are materialized below `%APPDATA%\com.deepshell.agent\runtime-cache\native\win32-x64\<16-char SEA digest>`; the cache verifies and repairs file-by-file against the recorded digests, rebuilds after crash residue, and keeps generation locking;
- **Packaging gates**: NSIS installer, portable ZIP, three schema 6 package manifests, the schema 3 package report, per-platform source-input digests, and size gates with the two declared exceptions below;
- **Windows self-spawn dispatch** (`W2-F007`/`W2-F008`, see section 8): the SEA entry now dispatches both self-spawn paths - pkg's `child_process` marker (`PKG_EXECPATH`) and the Windows native `CreateProcess` used by the DSH subprocess Job runner and the `windows-acl` sandbox runner - and keeps script arguments at `process.argv.slice(2)`.

## 5. Declared gate exceptions (user-confirmed, disclosed)

Two gates are declared as exceptions in `runtime/manifest/windows-gate-exceptions.json`. The declarations are explicit and auditable, the acceptance tooling only passes the declared items, and the schema 3 report records them in its `gateExceptions` array. Undeclared overruns still block.

| Exception | Requirement | Measured | Rationale |
| --- | --- | ---: | --- |
| `warmRss` | +20% / +64 MiB | 296,224 KiB vs 194,864 KiB (+52.0%, +101,360 KiB) | The Windows Node SEA keeps its raw asset archive (about 59.5 MB) resident as private memory; on macOS the same data is file-backed and reclaimable (macOS measured about +8.3%). This is a platform implementation difference the application layer cannot remove. |
| `windowsNsis` | +10% | 86,519,084 B (+52.4%) | The embedded Zstd archive cannot be compressed further, while the v0.1.4 NSIS compressed the `node_modules` text with a high LZMA ratio. The portable ZIP stays below its baseline (-7.6%). |

## 6. Known limitations (recorded honestly)

- The preview is unsigned: Windows SmartScreen reputation warnings and macOS Gatekeeper prompts are expected on fresh machines. On the acceptance machine SmartScreen did not warn (it may have been relaxed there); this needs a human check on a clean machine;
- CI artifacts are build gates only and are not part of the release assets;
- Not exercised in this version: the system shutdown/logout path, GUI uninstall-prompt interaction, cleanup timeout injection, data rollback, and the `REL-025` macOS scope (the quarantined-record retirement fix stays Windows-only);
- The `dsh web --open` browser hand-off path is not usable inside the SEA runtime (it self-spawns `node --input-type=module --eval`); the desktop app always launches with `--no-open`, so the path is unreachable in the app;
- An orphaned SEA sidecar can survive an abnormal parent kill; the ownership registry and the uninstall hook terminate it on the next controlled start or uninstall (verified on real hardware);
- The locally configured npm mirror (`registry.npmmirror.com`) exposes no audit endpoint; `pnpm security:audit` therefore pins the official `registry.npmjs.org` for advisory queries (override with `DEEPSHELL_AUDIT_REGISTRY`), and a non-dry-run audit fails closed (non-zero exit) if any sub-audit is not a real completed result.

## 8. Post-acceptance review fixes (Windows SEA stage)

The Windows stage ran the review-fix-loop and closed the following findings before this handoff (all re-verified on the final artifacts):

- `W2-F001` (blocker): 64-char cache generation directories exceeded `MAX_PATH` under real app data, so sharp/koffi failed to load; the generation directory is now the first 16 characters of the SEA digest;
- `W2-F002` (blocker, accepted exception): warm RSS exceeded the gate; declared and disclosed;
- `W2-F003` (blocker): a v0.1.4 to v0.1.5 upgrade left the legacy `runtime/node` + `runtime/dsh` tree behind; the NSIS `POSTINSTALL` hook now removes exactly those directories;
- `W2-F004` (blocker): every tool that spawns a subprocess failed on the real device because the Windows Job runner re-enters the SEA and the packaging bootstrap had to consume `DSH_SUBPROCESS_RUNNER`; the entry gained the exclusive dispatch chain (self-spawn script, runner selector, probe, CLI);
- `W2-F005` (blocker): `glob`/`grep` failed because the DSH search helper spawns `<executable>-rg.exe`, which cannot come from the VFS; the ripgrep sidecar is staged and verified with the SEA;
- `W2-F006` (medium): the host-mode package report did not read the local Windows manifests by default, so the first-run footprint was missing;
- `W2-F007` (blocker): the `pwsh` tool failed with `error: --profile <name> is required` because the `windows-acl` sandbox wraps the command into a runner argv and the DSH Windows Job runner spawns it through native `CreateProcess`, which never carries `PKG_EXECPATH`; the entry now also recognizes an absolute snapshot script in `argv[2]`;
- `W2-F008` (high): self-spawned snapshot scripts lost their first argument because argv normalization removed both the entry placeholder and the script path; it now removes only the placeholder, so script arguments stay at `argv[2]`;
- `W3-F001` (medium, audit consistency): the gate-exception declaration had hard-coded measured values from the confirmation round; because that file is a build input, any rebuild would make the recorded numbers drift while still reading as final values. Its rationale now states only the attribution and points at the authoritative measurements (the schema 3 report's `runtimeAcceptance.gates` and the size gate's `windowsNsis.bytes`), which this document discloses. Fixed in commit `3e65099`; the artifacts were then rebuilt from the clean commit (input digest `58f4d1ae…` → `ae23c46e…`; the SEA executable bytes were unaffected: `a0f12d51…`).

The fix is covered by permanent probes: `self-spawn-shapes` asserts the argument contract for both self-spawn paths, and the `subprocess-chain` probe covers `cmd`, `powershell`, `pwsh`, and the `sandbox-acl` chain (Job runner to native `CreateProcess` to ACL runner to a restricted-token child).

### 8.1 W3b rework (evidence integrity and delivery hygiene)

The Windows handoff audit found that the W3 package carried contaminated evidence documents even though the binaries were intact. The W3b rework closed five findings, rebuilt every asset from the clean commit `6e660f3` (input digest `dad2aba2…`; the SEA executable bytes are unchanged at `a0f12d51…`), and re-ran the affected evidence chain; CI run `36319913120` (success) gates the same commit:

- `F-1505-WR001` (high, audit integrity): the unit tests invoked `security-audit.mjs --dry-run`, which still wrote the official `runtime/staging/security-audit.json`, so the package shipped four `dry-run` entries under a top-level `completed` status while a real audit had run earlier. The script now takes an explicit `--output`; dry-run never writes the official path; a non-dry-run audit exits non-zero when any sub-audit is not a real completed result (`dry-run`/`tool-missing`/`failed`/`audit-error`/`completed-unparseable`/empty output); the top-level status is `completed` only when all four audits really ran. Regression tests prove `pnpm check` no longer modifies the official audit or route-check files;
- `F-1505-WR002` (high, route-check integrity): `windows-route-check.json` shipped as `windows-preflight-incomplete` because MSVC detection only looked for `cl.exe` on `PATH`, and the unit test overwrote the official report. Detection now falls back to `vswhere` and the standard Visual Studio install paths, test runs are isolated with `--output`, and a Windows preflight that is not `windows-preflight-pass` exits non-zero;
- `F-1505-WR003` (medium, document status conflicts): the process documents were synchronised to the real state (requirements/design/implementation-plan headers; `w0`/`w1`/`w2` explicitly marked as stage snapshots superseded by W3/W3b; a final resolution record appended to the W2 acceptance document); genuinely unexecuted items stay unexecuted;
- `F-1505-WR004` (medium, log hygiene): evidence logs carried a real `C:\Users\<name>` path, UTF-8 BOM/CRLF, and GBK-console mojibake. Command outputs are now captured through a per-line UTF-8/GBK-aware decoder, user directories are replaced with `%USERPROFILE%`, ANSI sequences are stripped, and every text file is UTF-8 (no BOM) + LF; raw `.lnk` shortcut backups (computer name and local paths) are replaced by a structured summary; an automated scan of the final package records zero findings;
- `F-1505-WR005` (medium, delivery format): the outer ZIP used `\` path separators, which makes macOS `unzip` warn and exit non-zero. The package is now written by a `/`-only writer and validated by parsing the raw ZIP central directory (no backslashes, absolute paths, traversal entries, symlinks, or duplicate names); `SHA256SUMS.txt` keeps `/`-relative paths.
