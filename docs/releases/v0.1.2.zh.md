# DeepShell Agent v0.1.2 DSH Runtime Refresh 收口

> **产品：** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **版本：** `v0.1.2`
>
> **状态：** 源码实现与本地 macOS arm64 developer-preview 包验证已完成。本次收口已授权发布 macOS developer-preview release。Windows installer 验收、真实 Provider API 验收、Developer ID 签名、公证和正式签名分发仍是独立门禁。
>
> **日期：** 2026-09-11

## 1. 摘要

`v0.1.2` 将 DeepShell Agent 从 `v0.1.1` 发布硬化基线刷新到上游 DeepSeek Harness `0.1.5-rc.1` compatibility set（兼容集合）。

本版本目标刻意收窄：接入固定版本的上游 DSH runtime，获得 DeepSeek `deepseek-flash` / `DeepSeek-V41-Flash` 模型目录优化；保持官方 DSH Web UI 和官方扩展点架构不变；保留现有凭据与权限语义；并在升级后的 Profile 写入 `DSH_HOME` 前，为 DSH Session 数据增加 fail-safe（失败安全）的本地备份保护。

## 2. 已实现范围

| 领域 | 状态 | 说明 |
|---|---|---|
| 版本元数据 | 已实现 | App package、Tauri config、Rust package、runtime lock、schema、一方 DSH Bundle 和 lockfile 均已更新为 `0.1.2` / `@deepseek-ai/dsh@0.1.5-rc.1`。 |
| Runtime refresh | 已实现 | `runtime/manifest/runtime-lock.json`、根 `pnpm-lock.yaml` 和 `runtime/manifest/dsh-install/package-lock.json` 已锁定 DSH `0.1.5-rc.1` compatibility set。 |
| Peer dependency 稳定性 | 已实现 | 根 pnpm 解析通过 `.npmrc` 禁用自动安装 peer dependency，避免 stale DSH peer package 被静默拉入源码依赖图。 |
| Profile refresh | 已实现 | `pnpm profile:prepare` 基于 DSH `0.1.5-rc.1` 重新生成 ignored Profile template；`pnpm profile:verify` 校验 Bundle/Profile/Preset 关系与 fingerprint。 |
| DeepSeek V4.1 Flash 模型目录契约 | 已实现 | Contract test 断言上游 DeepSeek adapter 包含 `deepseek-flash`、显示名 `DeepSeek-V41-Flash`、text/image input modality，以及 `systemPromptUpdate: in-history`。 |
| Session 升级保护 | 已实现 | Tauri 在物化升级后的 Profile 之前，为 `dsh-home/sessions` 创建有限本地备份；同一升级对跳过重复备份；元数据不写绝对路径；备份目录数量有上限。 |
| 失败安全备份行为 | 已实现 | Unit test 覆盖元数据、有限保留、不复制 workspace、幂等跳过重复备份，以及备份失败不删除源 Session 数据。 |
| 真实旧 Session 升级验收 | 待完成 | 代表性的 `v0.1.1` Session 打开/迁移验收仍是提升到 developer preview 之外前的手工门禁，并在 Roadmap 中单独跟踪。 |
| 公开文档 | 已实现 | README、Roadmap、third-party notices 和版本收口文档已同步 `v0.1.2` / DSH `0.1.5-rc.1` 源码基线。 |

## 3. 明确非范围与剩余门禁

本收口不声明：

- Windows x64 installer 在真实 Windows 设备或 CI 中验收通过；
- Windows WebView2 首次启动、退出、进程树清理或卸载验收通过；
- `deepseek-flash` / `DeepSeek-V41-Flash` 真实 DeepSeek API 调用验收通过；
- macOS Developer ID 签名；
- Apple notarization；
- Windows code signing；
- 正式签名/公证二进制公开分发；
- `dsh-home/sessions` 之外的用户数据备份；
- 代表性的真实 `v0.1.1` Session 打开/迁移验收；
- workspace 备份、workspace migration 或 workspace cleanup；
- 新增第二套 credential、permission、model registry、Session runtime 或 Web UI fork。

当前 macOS 包仅是本地验证通过的 developer-preview 包。本次收口已授权 Git tag 创建和 GitHub prerelease asset 上传；提升到 developer preview 之外仍需完成上述剩余门禁。

## 5. 公开/本地产物边界

可提交到公开仓库的内容包括：

- 源码；
- lock manifest；
- 测试；
- README / Roadmap / release closeout / third-party notice 更新；
- 公开构建与验证脚本。

以下内容默认仍保留在 ignored/local 范围，不进入公开源码仓库：

- `docs/plans/`；
- `runtime/staging/`；
- `runtime/node/`；
- `runtime/dsh/`；
- `runtime/profile-template/`；
- 本地 `.app`、`.dmg`、`.exe`、日志、截图、诊断包和验收证据。

升级前 Session 备份属于用户 application-data 目录下的运行时数据，不是仓库产物，不能提交。

## 6. 发布结果与建议

`v0.1.2` 以源码实现基线 + 本地验证通过的 macOS arm64 developer-preview 包产物收口。它适合维护者继续手动测试 DSH `0.1.5-rc.1` runtime refresh。

将本版本提升到 developer preview 之外前建议：

1. 从既有 `v0.1.1` app-data 目录执行一次真实升级测试，确认代表性 Session 仍可打开或正确迁移；
2. 在有效 DeepSeek API Key 和 gateway 可用时，执行一次真实 `deepseek-flash` / `DeepSeek-V41-Flash` Provider 调用；
3. Windows 二进制发布继续等待 Windows x64 真机或 CI 验证实际 installer；
4. 签名/公证门禁完成前，任何公开二进制 release 都应保持 developer preview。
