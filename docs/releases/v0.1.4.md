# DeepShell Agent v0.1.4 Packaging-Efficiency Release

> **Product:** DeepShell Agent
>
> **Tagline:** A desktop agent powered by DeepSeek Harness.
>
> **Version:** `v0.1.4`
>
> **Release nature:** a packaging-efficiency release: per-platform runtime trimming, a Windows portable (no-install) distribution, platform-native menus, and bounded runtime-cleanup hardening.
>
> **Status:** **Windows x64 acceptance is recorded** (WIN-01 to WIN-13 measured on real Windows 11 x64). The macOS arm64 side of the packaging work was implemented and verified during the macOS stage of this version, but the final joint regression (C0), the review closeout (C1/C2), and the signed-distribution gates are still pending. This document must not be read as a completed macOS acceptance.
>
> **Date:** 2026-09-16

## 1. Scope

- **Per-platform runtime trimming** (`REL-022`): each installer carries only the Node runtime its platform executes;
- **Windows portable ZIP** (`REL-023`): a second Windows distribution form that runs from an extracted folder;
- **Platform-native menus** (`DESK-023`): macOS keeps its application menu, Windows gets `File > Exit` and `Help > About DeepShell Agent`;
- **Exit and uninstall cleanup** (`REL-024`): the Windows side now reports a failed tree termination honestly, and the NSIS uninstaller runs a restricted maintenance command that removes residue belonging to the current installation before deleting files;
- **Package-size regression gates** (`QA-011`, package-size scope): tracked baselines, a per-platform source digest, and a three-manifest size gate.

## 7. Post-acceptance review fixes

A full review of the Windows-stage changes, followed by two further review rounds, found and fixed a set of correctness and repeatability issues before publication; the measurements above were re-taken on the final build (`977da59`, win32-x64 source-input digest `37937d93…`).

- **Process-identity fail-closed hardening**: the uninstall cleanup no longer ignores a failed identity check and no longer acts on non-active ownership records, so a reused PID can never be terminated (a regression test injects exactly that scenario); process liveness and path verification now distinguish "unknown" from "dead" and refuse to continue in the unknown state; all external PowerShell/taskkill calls run with timeouts.
- **Repeatability**: a `package:windows:installed-tree` command now orchestrates install → capture → uninstall → environment restore, with the registry/shortcut restore ordered after the uninstaller has fully finished (a race that could silently drop the restored registry key).
- **Boundaries**: the CI workflow uploads the three platform manifests; release staging accepts `--require-assets` for combined-staging checks; the pre-uninstall hook stays silent in silent installs and waits briefly for file handles; About metadata reads Node/DSH versions from the runtime lock instead of hardcoded strings; package manifests no longer duplicate the whole tree under `resources`.
- **Second review round**: the installed-tree orchestration now fails closed when the uninstaller removal cannot be confirmed (an aborted uninstall can no longer delete a half-installed directory and restore the registry as if the environment were clean) and rejects any `--install-root` outside `runtime/staging/install-tree-v<version>`; startup recovery quarantines a record and continues when process identity cannot be verified (for example when PowerShell is blocked by policy), while exit and uninstall paths stay fail-closed; `taskkill` waits are bounded by the caller deadline, and tar/cargo/strings helper calls carry explicit timeouts. The re-run Windows smoke matrix (clean state, app-running, window-close exit, killed-app orphan cleanup, uninstall with registry restore) passed on the final build, and CI run `35218713142` completed green on the same commit.
- **Third review round**: the NSIS hook now clears and presets the failure code before `ExecWait` (`ClearErrors` / `StrCpy $R0 15` / `IfErrors`), so a maintenance helper that fails to start can never be read as "clean"; large-asset hashing is streamed in the size gate, package report, release staging and the runtime helper; the package report also verifies the portable ZIP against the on-disk archive; redaction covers the workspace root; the installed-tree uninstall settle window is 90 s (with a final re-check after the deadline) and the portable tar timeout is 30 minutes, so slow-but-legitimate operations on scanning hosts are no longer killed. The re-run Windows smoke matrix passed on the final build (clean 0 twice / app-running 13 / window-close exit with no residue / orphan cleanup 0 / uninstall with registry restore), and CI run `35245353581` completed green on the same commit.
